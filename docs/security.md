# セキュリティ方針（v0.1）

個人情報（要配慮個人情報を含む）を扱うため、以下を必須とする。

## 1. 前提
- クラウド型だが、氏名・生年月日・学校名・医療情報等の直接識別子はLLMに送信しない。
- `src/core/anonymize.py` による仮名化をAPIサーバ側で強制。
- 対応表（仮名↔実名）はDBの暗号化領域または揮発メモリのみ。ログ・LLM履歴に残さない。

## 2. 認証・認可
- 学校単位テナント＋ロール：管理者 / 管理職 / 担任・担当 / 閲覧のみ
- 学年・学級スコープで参照制限。異動時は即時無効化。
- 多要素認証（TOTP等）を管理職・管理者に必須化（本番）。

## 3. 暗号化・保管
- 通信：TLS1.2以上、HSTS
- 保存：DB暗号化（Postgres TDE相当 / マネージド暗号化）、バックアップ暗号化
- リージョン：日本国内。AI事業者の学習利用オプトアウト設定。
- 出力PDFの透かし・印刷ログ。ダウンロードは監査対象。

## 4. 監査・同意
- 操作ログ：誰が・いつ・どの児童・何を変更・AI使用有無・承認者
- 保護者確認：面談日・確認方法・合意フラグを計画に紐付け
- 保存期間・削除：卒業・転出後の保管年限を自治体ルールに合わせ設定、期限後安全削除

## 5. 運用注意
- 教員端末の覗き見・置き忘れ対策（自動ロック、短時間セッション切れ）
- 外部送信前の再匿名化チェックをCI/テストで担保（`test_security.py` 予定）
- 将来オプション：校内LLM / 閉域APIへの差し替え口を `AI Gateway` に確保

## 6. 禁止事項
- 実名・学校名入りのままAIプロンプト送信
- AI文案の無承認確定・保護者共有
- 個人情報を含むテンプレートの無暗号メール送信

## 7. 実装済み対策（v0.10〜）
- CSVインジェクション対策（`=` `+` `-` `@`始まりの値は `'` 前置き）
- ログアウトでサーバ側セッション削除
- アップロード10MB上限・破損ファイルは400で拒否
- ダウンロードのファイル名・様式IDの厳密検証（経路 traversal 防止）
- ログイン試行制限（5分10回・単一プロセス内。本番多ワーカー時は前段での制限を併用）
- 初期パスワードの変更強制（must_change_pw）
- 権限境界：viewerは閲覧のみ（差し込み・出力・引継ぎは教員以上）
- 所有権境界：担任は自分の作成・同学年の計画のみ操作可（ID直指定の他者参照は403）
- AI利用制限：1ユーザ5分30回（外部LLMのコスト・乱用防止）
- プレビュー（計画指定時）は監査記録
- 入力上限：計画データ500KB・基本項目100字・映射2000件・認証入力200字
